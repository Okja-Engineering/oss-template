# 0001 oss-template: spec

**Status:** draft. **Decider:** Matthew Van Dusen. **Rests on:** [`intent.md`](intent.md), [`decisions.md`](decisions.md), [`research.md`](research.md).

What the workspace does, stated so each line can be checked. Each acceptance criterion (AC) names its proof: a `bin/check` check, a suite under `tests/`, a CI job, or a person reading. Unmarked ACs gate the slice the plan assigns them to; **launch** ACs gate launch. "Ruling N" is one of the decider's rulings and "decision N" a decision made under his delegation, both in [`decisions.md`](decisions.md). "Measure N" is the intent's numbering. "TAC N" cites AC N of the superseded template spec (`git show b368d09:docs/work/0001-oss-template/spec.md`), whose foundation ACs this spec carries by reference (§ 4); TAC44's M5, M6 and M7 are measures 6, 7 and 8 here.

## Terms

- **Workspace:** this repository. **Run:** one pass through the stages for one repository name. **Produced repository:** what a run makes. **Target:** the directory a run renders into, `<TARGET_ROOT>/<NAME>`, outside the workspace. **Operator:** the person working through a run's checkpoints. **Published:** a run whose `publish.md` records an outward step done, or one of whose intended steps is seen done on the remote (decisions 101, 111, 120). **Attempted:** a run with an intent line in `publish.md` but neither; it resumes or is abandoned.
- **Foundation:** `foundation/`, the complete product tree (decision 68). A file there is **verbatim**, a **template** (`PATH.tmpl`) or a **variant** (`PATH.VALUE`, chosen by the field that selects `PATH`; decision 78). Nothing outside `foundation/` reaches a produced repository, and no product check runs on anything but a produced tree (decision 89).
- **Answers file:** a run's `stages/01-ask/output/<name>/answers.env`, one `FIELD=value` per line, read as data and never sourced. **Render fields** reach the produced tree; the others steer scripts only.
- **Fingerprint:** the git tree id of a rendered tree, file modes included (decision 53), built under hermetic git (AC10).
- **Share** (ruling 15): a step is **deterministic** (a script), **orchestration** (the contract's order and checkpoints) or **judgment** (the agent).
- **Reserved decisions:** TAC's, plus approving a publish plan (a decider in the workspace's `GOVERNANCE.md`, decision 70) and changing any § Deciders (decision 45).

- **AC5** **The workspace's checks are its own** (decisions 89, 95, 96, 102): `commits`, `pr`, `secrets`, `never-publish`, `scripts`, `claims`, `trace`, `docs`, `workflows`, `disclosure`, `setup`, `foundation`, each a thin caller of `foundation/bin/lib/*.sh` with explicit parameters (`never-publish` passes its own list, `.githooks/never-publish`; `docs` passes the workspace's `GOVERNANCE.md`, the roots `docs/adr/` and `docs/work/`, and the base), never invoking a product check. ## 2. The stages

Scripts do every write (decision 56). ICM keeps process out of code, and so does this: order and checkpoints stay in the contracts, and only the transforms are scripts, because prose cannot meet measure 5. `docs/workflow.md` says the workspace is pre-launch until S10 merges and G4 passes: until then `main` may hold an incomplete foundation. Four departures from ICM ([research](research.md), source 19) are recorded (decisions 85, 99, 108): the target is a handoff outside `output/`; `references/` exists only when it holds files; Layer 0 is `@AGENTS.md`, with routing in `CONTEXT.md` and no What-to-Load table, since each contract's Inputs is its load list; and stage 02 has a checkpoint before `--replace`.

| Stage | Deterministic (script) | Orchestration (contract) | Judgment (agent) |
|---|---|---|---|
| 01-ask | `bin/ask run`, `confirm`, `--redo --remove` | checkpoints: confirm the answers; remove the target before `--redo` | drafts `NAME`, `DESCRIPTION`, `VISIBILITY`; audits the description |
| 02-render | `bin/render`, `--replace --remove` | a checkpoint: remove the target before `--replace` | none |
| 03-verify | `bin/verify`, `--install` | stop on failure; a checkpoint: remove a target unlike its render; route to 01, 02 or the workspace | diagnoses the failure |
| 04-publish | `bin/publish --plan`, `--apply`, `--watch`, `--abandon` | checkpoints: a listed decider approves the plan line; the operator abandons an attempted run | presents the plan; diagnoses a failed run |

**01-ask.** Inputs: `../../shared/answers.tsv`. Process: draft the run fields from the ask; run `bin/ask run NAME FIELD=value…`; show the file. Checkpoints: the operator confirms (`bin/ask confirm NAME --by "<operator>"`), or gives edits; edits to an unpublished run first need the operator's yes to "remove <the target `render.md` names>", then `bin/ask run NAME --redo --remove "<path>" …` (decisions 94, 123). Audit: `DESCRIPTION` is one line meeting upstream's [writing bar](https://github.com/Okja-Engineering/ai-native-sdlc/blob/main/AGENTS.md#write-it-the-way-you-would-say-it). Outputs: `answers.env`, `confirmed.md`.
**02-render.** Inputs: `../01-ask/output/<name>/confirmed.md`. Process: `bin/render NAME`; for a new render of the same answers, the operator's yes to "remove <path>", then `bin/render NAME --replace --remove "<path>"`. Outputs: `render.md`.
**03-verify.** Inputs: `../02-render/output/<name>/render.md`. Process: `bin/verify NAME`. On failure, stop and route as `docs/workflow.md` sets out: a target unlike its render, a dirty target or a partial run: a checkpoint here, where the operator approves "remove <the target `render.md` names>"; with the yes, to 02 (`--replace --remove "<path>"`), and without it the target is left alone (decision 118); a check, suite or audit failing on the foundation, to a workspace change merged like any other, then 02; failing on an answer, to 01 (`--redo`); a missing tool, install it and rerun 03; a run verified but not installed, `bin/verify NAME --install` once the cause is cleared (decision 161). The target is never edited by hand. Once verify installs the target's `.git`, that repository is the operator's: verify never reads it or runs git in it, and the operator runs `bin/setup` there before working in it (decision 158). Outputs: `verify.md`, `repo.git`, `judge/`.
**04-publish.** Inputs: `../03-verify/output/<name>/verify.md`. Process: `bin/publish NAME --plan`; checkpoint; `bin/publish NAME --apply "<line>" --approver "<decider>"`; `bin/publish NAME --watch`. A run may stop after 03 with a verified local repository. An attempted run is resumed with `--apply`, or, while nothing reached GitHub, abandoned at a checkpoint with `--abandon`. Once published, a run is never redone or replaced: a mistake, or a failed watch, is fixed in the produced repository through its own pull request process. Outputs: `publish.md`.

- **AC10** **Hermetic git** (decisions 90, 104, 112, 128, 132, 135, 137, 143, 154, 156, 159, 166, 167). `bin/lib/git.sh` sets this environment for every caller. Render, the fingerprint, verify (`repo.git`, `judge/` and the install's private repository) and publish's mirror first unset every variable `git rev-parse --local-env-vars` names, `GIT_ATTR_SOURCE`, `GIT_DEFAULT_HASH`, and every `GIT_AUTHOR_*` and `GIT_COMMITTER_*`; then set `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_ATTR_NOSYSTEM=1`, `GIT_NO_REPLACE_OBJECTS=1` and `GIT_DEFAULT_REF_FORMAT=files` (git before 2.45 knows only `files`; from 2.45 the variable pins it; decision 156), and, through `GIT_CONFIG_COUNT`, `GIT_CONFIG_KEY_<n>` and `GIT_CONFIG_VALUE_<n>` so every git process they start inherits them while it keeps the environment, `core.attributesFile=/dev/null`, `core.excludesFile=/dev/null`, `core.fileMode=true`, `commit.gpgsign=false`, `core.hooksPath=/dev/null` and `core.fsmonitor=false`; its one version gate, comparing major and minor numerically, refuses a git older than 2.36. A process that resets the environment, as the produced suites' fixture library does, escapes these settings, which is one reason verify never runs git with the target's `.git` (AC13, decision 155). Repositories are made with `git init --template= --object-format=sha1`; the fingerprint is built in a private `GIT_DIR` with a fresh index, never the workspace's or the target's `.git`; before any fingerprint of the target, render and verify run **the walk**, in `bin/lib/render.sh` and with no git (decisions 159, 166): it lists every non-directory under the target, NUL-delimited, without following symbolic links and leaving out only the top-level entry named `.git`, sorted with duplicates kept, and requires that sequence to equal render's file list; it also refuses a directory that is not the parent of a listed path. A nested `.git` with anything in it is therefore an extra path, and an empty one an extra directory. Each index is built from that list, refusing a nonzero exit from `git add` and an index whose `ls-files -z` differs from the list, since git adds nothing under a nested repository and still exits 0. *`test_render.sh` and `test_verify.sh`, one planted case each, each asserting what its setting protects (the fingerprint; the root commit's identity and tree; the object and ref formats of `repo.git` and the installed `.git`; or that nothing planted runs), and first seen failing with its setting removed (decision 167): a global config excluding `.claude/` and `bin/`, with `core.fileMode=false` and `commit.gpgsign=true`; `$XDG_CONFIG_HOME/git/ignore`, and `$XDG_CONFIG_HOME/git/attributes` holding `* text` over a file with CRLF endings; a git template directory whose `info/attributes` names a filter its `config` defines; `GIT_ATTR_SOURCE=HEAD`; `GIT_DEFAULT_HASH=sha256`; `GIT_DEFAULT_REF_FORMAT=reftable`, after which both repositories still use `files` with no `extensions.refstorage`, so an operator's git before 2.45 can read them (it fails without the pin on git 2.45 and later, and reports itself skipped on an older git); render run from a pre-commit hook during `git commit -a`, with `GIT_INDEX_FILE` set; the workspace's `.git` gaining no object or ref; the walk refusing a file named with a newline, an empty extra directory and an empty nested `.git`. `tests/test_git_lib.sh`: a stub `git --version` reporting 2.35.9, refused; 2.36.0, 2.100.0, 3.0.0 and `2.50.1 (Apple Git-155)`, accepted.*

- **AC13** `bin/verify NAME [--install]` (decisions 118, 119, 122, 131, 155, 157, 158, 161, 162, 165) never runs git with the target's `.git` or index, and reads nothing in that `.git`. A run is a **first run** when `verify.md` holds no pass for this run name and the target holds no entry named `.git` (a dangling symbolic link counts); a **rerun** when it holds one; anything else is refused before any check runs and routed to stage 03's removal checkpoint. Its outputs, under `stages/03-verify/output/<name>/`, are `verify.md`; `repo.git`, a bare repository (`git init --bare --template= --object-format=sha1 -b main`) made afresh by each first run, holding the root commit on `refs/heads/main`; `judge/`, the judging copy, made afresh by every run; and, during an install, `handover/`. Produced code run in `judge/` can reach these, so after it has run, verify reads from `repo.git` only content-addressed objects it asserts (decision 165). **A first run** walks the target (AC10); fingerprints it into `repo.git` through a private index, requiring the tree to equal `render.md`'s fingerprint; fills a fresh `judge/` with `git archive` of that tree from `repo.git`, before any produced code has run, so `judge/` holds exactly the bytes to be committed (decision 162); gives `judge/` its own `.git` (`git init --template= --object-format=sha1 -b main`) and adds render's file list there; runs, in `judge/`, `bin/check --staged` (AC22's staged mode with no `HEAD`: the tree checks, plus `secrets` and `never-publish` on the index, where every line is added; decision 131), `tests/run-all.sh` and the email audit (AC14); and only if all pass makes the root commit in `repo.git`: `git commit-tree` of that tree with message `Initial commit`, author and committer set from `COMMIT_IDENTITY` (for every write to `repo.git`, the install's repository and the mirror, decision 160) after every inherited `GIT_AUTHOR_*` and `GIT_COMMITTER_*` is unset, its author, committer and tree asserted, and only then `git update-ref refs/heads/main <commit> ""`, expecting no old value. No hook runs for that commit. `verify.md` then records the pass: each command, exit code, the SHA and its tree. A run failing before the commit records the failure and leaves no commit in `repo.git` and no `.git` in the target. **The install** (decision 161) follows and runs no git with the target's `.git`: verify builds the operator's repository privately in `handover/`, a non-bare `.git` (`core.bare=false`, no `core.worktree`) made by the recipe, with `refs/heads/main` fetched from `repo.git` at the recorded SHA and no `FETCH_HEAD` or reflog written, `HEAD` on `main`, and an index from `read-tree` of the SHA then `update-index --refresh` with the target as work tree, under the private config, so no filter or hook in the target can run; it asserts `HEAD` at the SHA; then it runs `mkdir <target>/.git`, which fails on any existing entry, copies `handover/`'s contents in with `cp` and no git, and removes `handover/`. On any failure from building `handover/` to the end of the copy, verify removes the directory it made in the target, only while that is still a real directory, and `verify.md` records the run as verified, not installed; `bin/verify NAME --install` retries the install alone and refuses while the target holds an entry named `.git`. A process writing into the target's `.git` between the `mkdir` and the copy is out of scope (a local attacker running as the same user); nothing verify runs reads it afterwards. From then on the target's `.git` is the operator's. **A rerun** (also `--check`) walks the target and fingerprints it into a fresh private `GIT_DIR`, requiring the tree `verify.md` records; fills a fresh `judge/` with `git archive` from that private `GIT_DIR`, never from `repo.git`; and repeats every check there without committing, so it judges as the first run did, every line added. A walk or fingerprint that differs is refused and routed to the removal checkpoint.
