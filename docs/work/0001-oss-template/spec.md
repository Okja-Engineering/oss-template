# 0001 oss-template: spec

**Status:** draft. **Decider:** Matthew Van Dusen. **Rests on:** [`intent.md`](intent.md), [`decisions.md`](decisions.md), [`research.md`](research.md).

What the workspace does, stated so each line can be checked. Each acceptance criterion (AC) names its proof: a `bin/check` check, a suite under `tests/`, a CI job, or a person reading. Unmarked ACs gate the slice the plan assigns them to; **launch** ACs gate launch. "Ruling N" and "decision N" cite [`decisions.md`](decisions.md), whose numbered items are all decisions. "Measure N" is the intent's numbering. "TAC N" cites AC N of the superseded template spec (`git show b368d09:docs/work/0001-oss-template/spec.md`), whose foundation ACs this spec carries by reference (§ 4); TAC44's M5, M6 and M7 are measures 6, 7 and 8 here.

## Terms

- **Workspace:** this repository. **Run:** one pass through the stages for one repository name. **Produced repository:** what a run makes. **Target:** the directory a run renders into, `<TARGET_ROOT>/<NAME>`, outside the workspace. **Operator:** the person working through a run's checkpoints.
- **Foundation:** `foundation/`, the complete product tree (decision 68). A file there is **verbatim**, a **template** (`PATH.tmpl`) or a **variant** (`PATH.VALUE`, chosen by the field that selects `PATH`; decision 78). Nothing outside `foundation/` reaches a produced repository, and no product check runs on anything but a produced tree (decision 89).
- **Answers file:** a run's `stages/01-ask/output/<name>/answers.env`, one `FIELD=value` per line, read as data and never sourced. **Render fields** reach the produced tree; the others steer scripts only.
- **Fingerprint:** the git tree id of a rendered tree, file modes included (decision 53), built under pinned git (AC10).
- **Share** (ruling 15): a step is **deterministic** (a script), **orchestration** (the contract's order and checkpoints) or **judgment** (the agent).
- **Reserved decisions:** TAC's, plus approving a publish plan (a decider in the workspace's `GOVERNANCE.md`, decision 70) and changing any § Deciders (decision 45).

Produced repositories follow the same pattern: a short `AGENTS.md` (AC1), rules scoped by path (TAC14), skills and the reviewer loaded on demand (TAC20, TAC21).

- **AC1** `CLAUDE.md` is exactly `@AGENTS.md` and `AGENTS.md` is at most 80 lines: in the workspace by `disclosure`, in every produced repository by `agents` (TAC10, its 100 lowered by ruling 16). *`tests/test_check_disclosure.sh`; `test_check_agents.sh`.*
- **AC2** `disclosure` refuses: `CONTEXT.md` over 60 lines, or a routing table not naming each `stages/NN-slug/` exactly once; a stage folder not matching `NN-[a-z]+(-[a-z]+)*` or lacking `CONTEXT.md` or `output/.gitignore`; an `output/.gitignore` other than `*` and `!.gitignore`; any other tracked file under `output/`; a contract over 80 lines, or without `## Inputs`, `## Process` and `## Outputs`, with optional `## Checkpoints` and `## Audit` between the last two, in that order. *`test_check_disclosure.sh`, one fixture case each.*
- **AC3** **Inputs discipline** (ruling 16). Each Inputs row names one file in backticks, relative to its stage folder, that resolves to a tracked file or is `../NN-slug/output/<name>/FILE` listed in an earlier stage's Outputs. `disclosure` refuses a directory, a glob, an unresolved path, an input from the same or a later stage, and a file in `references/` that its stage's Inputs do not name. *`test_check_disclosure.sh`.*
- **AC4** **Workspace prose traces** (measure 4). The workspace's `claims` applies TAC13's rule to its Markdown, and its `trace` applies TAC12's to its agent files (`AGENTS.md`, `CLAUDE.md`, `CONTEXT.md`, every contract): each rule line links `docs/workflow.md`, `CONTRIBUTING.md` or `GOVERNANCE.md`, every relative link and anchor resolves, and each `.claude/settings.json` deny entry appears in `CONTRIBUTING.md` § Agent guards. Both read through the tree reader with `foundation/`, `docs/adr/`, `docs/work/` and `tests/fixtures/` excluded. *`tests/test_check_claims.sh`, `test_check_trace.sh`, on fixtures.*
- **AC5** **The workspace's checks are its own** (decisions 89, 95, 96): `commits`, `secrets`, `scripts`, `claims`, `trace`, `disclosure`, `setup`, `foundation`, each sourcing `foundation/bin/lib/*.sh` with explicit parameters and never invoking a product check. Its `bin/check` sources `foundation/bin/lib/dispatch.sh` over its `bin/checks/` and takes C4's arguments: `[CHECK…]`, `--range BASE HEAD [CHECK…]`, `--staged`, `commit-msg FILE`, `pr` (`PR_TITLE`, `PR_BODY`), `--list`; `--report` belongs to the product's `docs` check and exits 2 here. `bin/setup` sets `core.hooksPath` to `.githooks`, whose `commit-msg`, `pre-commit` and `pre-push` call `bin/check`. `commits` judges only commits not reachable from S1's merge commit, recorded when the check lands (decision 92). *`tests/test_check_cli.sh`, `test_setup.sh`, `test_check_commits.sh`: a pre-baseline 74-character subject passes, a later one fails.*

## 2. The stages

Scripts do every write (decision 56). ICM keeps process out of code, and so does this: order and checkpoints stay in the contracts, and only the transforms are scripts, because prose cannot meet measure 5. The target is a handoff outside `output/`, and `references/` exists only when it holds files; both depart from ICM (decisions 85, 99).

| Stage | Deterministic (script) | Orchestration (contract) | Judgment (agent) |
|---|---|---|---|
| 01-ask | `bin/ask run`, `confirm`, `--redo` | checkpoints: confirm the answers; before `--redo` | drafts `NAME`, `DESCRIPTION`, `VISIBILITY`; audits the description |
| 02-render | `bin/render`, `--replace` | a checkpoint before `--replace` | none |
| 03-verify | `bin/verify` | stop on failure; route to 01, 02 or the workspace | diagnoses the failure |
| 04-publish | `bin/publish --plan`, `--apply`, `--watch` | checkpoint: a listed decider approves the plan line | presents the plan; diagnoses a failed run |

**01-ask.** Inputs: `../../shared/answers.tsv`. Process: draft the run fields from the ask; run `bin/ask run NAME FIELD=value…`; show the file. Checkpoints: the operator confirms (`bin/ask confirm NAME --by "<operator>"`), or gives edits; edits to an existing run first need the operator's yes to discarding its unpublished target, then `bin/ask run NAME --redo …` (decision 94). Audit: `DESCRIPTION` is one line meeting upstream's [writing bar](https://github.com/Okja-Engineering/ai-native-sdlc/blob/main/AGENTS.md#write-it-the-way-you-would-say-it). Outputs: `answers.env`, `confirmed.md`.
**02-render.** Inputs: `../01-ask/output/<name>/confirmed.md`. Process: `bin/render NAME`; for a new render of the same answers, the operator's yes to discarding the unpublished target, then `bin/render NAME --replace`. Outputs: `render.md`.
**03-verify.** Inputs: `../02-render/output/<name>/render.md`. Process: `bin/verify NAME`. On failure, stop and route as `docs/workflow.md` sets out: a target unlike its render, or a partial run, to 02 (`--replace`); a check, suite or audit failing on the foundation, to a workspace change merged like any other, then 02; failing on an answer, to 01 (`--redo`); a missing tool, install it and rerun 03. The target is never edited by hand. Outputs: `verify.md`.
**04-publish.** Inputs: `../03-verify/output/<name>/verify.md`. Process: `bin/publish NAME --plan`; checkpoint; `bin/publish NAME --apply "<line>" --approver "<decider>"`; `bin/publish NAME --watch`. A run may stop after 03 with a verified local repository. Outputs: `publish.md`.

- **AC6** `shared/answers.tsv` has columns `field scope render selects pattern default question`. Setup fields, with patterns and defaults (`OWNER` standing for its value): `OWNER` (a GitHub login, `[A-Za-z0-9](-?[A-Za-z0-9])*`, at most 39; `Okja-Engineering`); `DECIDERS` (`;`-separated names); `CODEOWNERS` (`@login` or `@org/team`; `@OWNER/maintainers`); `COC_CONTACT` (an `https://` URL or an email address, or the default sentence `not yet set, so launch waits on it`); `WORKSPACE_URL` (`https://github.com/<owner>/<repo>`; `https://github.com/Okja-Engineering/oss-template`); `COPYRIGHT_HOLDER` (`OWNER`); `COMMIT_IDENTITY` (`Name <address>`; `OWNER <OWNER@users.noreply.github.com>`); `TARGET_ROOT` (`~/Development/OWNER`). Run fields: `NAME` (`[a-z0-9][a-z0-9._-]*`), `DESCRIPTION` (one line), `VISIBILITY` (`public` or `private`), `LICENSE` (`apache-2.0` or `none`, selecting `LICENSE`; default `apache-2.0` when public, `none` when private; decision 74). Render fields: all but `COMMIT_IDENTITY`, `TARGET_ROOT`, `VISIBILITY`. One parser, `bin/lib/answers.sh`, serves every script. *`tests/test_answers.sh`, incl. `$(touch x)` creating nothing, and values with non-ASCII letters, `&`, `\` and `=` kept.*
- **AC7** `bin/ask setup FIELD=value…` rewrites `setup/answers.env`; `bin/ask questionnaire` writes `setup/questionnaire.md` from the schema as ICM's rules ask: one flat numbered list, every question at once, each with its field, type and default. `bin/ask run NAME FIELD=value… [--redo]` writes the answers file (setup fields, run fields with their defaults, and `TARGET`, `~` expanded), sorted, LF endings; `--redo` first removes an unpublished run's target and later outputs. `bin/ask confirm NAME --by WHO` writes `confirmed.md` with who, when and the answers file's blob id. Refused, writing nothing: an unknown field; a value failing its pattern or holding a newline or `{{`; a free-text value holding a word from the union of `claims`' and `trace`'s lists in `foundation/bin/lib/rules.sh`, or a `DESCRIPTION` holding an email address (decision 73); a missing field; a setup field given to `run`; an existing run without `--redo`, or `--redo` on a published one; a non-empty target. *`tests/test_ask.sh`.*
- **AC8** `setup` refuses a `setup/questionnaire.md` other than `bin/ask questionnaire`'s output, and a `setup/answers.env` missing a field or failing a pattern. *`tests/test_check_setup.sh`.*
- **AC9** `bin/render NAME [--replace]` refuses answers without a `confirmed.md` naming their blob id, then reads `foundation/` at the workspace's committed `HEAD` (decision 71) through `foundation/bin/lib/tree.sh`. A verbatim file is copied byte for byte; a template has each `{{FIELD}}` replaced by its value, and a line that is exactly `- {{FIELD}}` repeated per list item; a variant is used for `PATH` when its `VALUE` equals the selecting field's; modes come from the tree. It writes the target only when absent or empty; `--replace` first empties an unpublished target that `render.md` names. Refused: a placeholder that is not a render field; a `{{[A-Z_]+}}` left after substitution; an executable template; a variant whose field selects nothing, or a selecting field with no variant for its value. `render.md` records the target, workspace SHA, answers blob id, the file list and the fingerprint. *`tests/test_render.sh` on a fixture workspace.*
- **AC10** **Pinned git** (decision 90). Render, the fingerprint and verify run git with `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`, `core.fileMode=true`, `commit.gpgsign=false` and no excludes file, and build each index from render's own file list, refusing a file extra to it or missing from it. *`test_render.sh` and `test_verify.sh` under a hostile global config: excludes `.claude/` and `bin/`, `core.fileMode=false`, `commit.gpgsign=true`.*
- **AC11** **Determinism (measure 5).** `bin/render` reads no clock, network, randomness or environment beyond its arguments, the answers file and the workspace's `HEAD`. Two renders of one answers file at one commit have the same fingerprint with `TZ`, `LC_ALL`, `HOME`, the working directory and `umask` varied. The fingerprint equals the target's tree id and is computed without creating `.git` there. No field is run-specific. *`test_render.sh`; across platforms, AC28's `m5` job.*
- **AC12** **Field effects.** Changing one render field changes exactly the product paths whose templates hold its placeholder, or that it selects; changing a non-render field changes nothing. *`test_render.sh`, every field.*
- **AC13** `bin/verify NAME`, on a target with no `.git`, requires its fingerprint to equal `render.md`'s; then runs, in the target, `git init -b main`, `bin/setup`, a root commit `Initial commit` authored and committed as `COMMIT_IDENTITY` (decision 82), `bin/check --range "" HEAD`, `tests/run-all.sh` and the email audit (AC14); requires `HEAD^{tree}` to equal the fingerprint; and records each command, exit code and the `HEAD` SHA in `verify.md`. On a target whose history is exactly that one root commit, it repeats every check without committing (also as `--check`); on any other `.git`, it refuses and names 02's `--replace` (decision 98). *`tests/test_verify.sh` on a fixture workspace: an edit after render refused; a planted failing check recorded; a rerun adds no commit; a partial run refused.*
- **AC14** **Email audit** (decision 63): `bin/verify` fails on an address in the rendered files other than at `example.invalid` or `users.noreply.github.com`, TAC § 3's tool signatures, or a render field's value; `git@github.com:` is not an address. *`test_verify.sh`.*
- **AC15** **Resume.** `bin/status [NAME]` prints, per run, its next step: 01 is complete when `confirmed.md` matches the answers; 02 when `render.md` names that answers blob and the workspace's `HEAD`; 03 when `verify.md` records a pass on that render; 04 when `publish.md` records a passing watch. After a failed 03 it prints that failure's remedy, never 04; after the workspace's `HEAD` moves past an unpublished render, it prints 02's `--replace`. *`tests/test_status.sh`, one case per state.*
- **AC16** `bin/publish NAME --plan` refuses a dirty workspace, a render from a commit other than `HEAD`, a workspace SHA not reachable from the remote default branch as last fetched (decision 93), and a target failing `bin/verify --check`. It prints one line naming every outward action: create `OWNER/NAME` as VISIBILITY with its description; turn off rebase merging (decision 11); on a public repository, turn on private vulnerability reporting (decision 39); push SHA to `main`; open the first issue. *`tests/test_publish.sh`, with a stub `gh` and a fixture remote.*
- **AC17** `bin/publish NAME --apply "LINE" --approver "NAME" [--basis TEXT]` refuses unless LINE equals the current plan and NAME is listed in the workspace's `GOVERNANCE.md` § Deciders (decisions 70, 97). Each step reads state first, so a rerun resumes without repeating one: an existing repository passes only when empty or holding `main` at SHA; the push is never forced; the first issue, `Produced by <WORKSPACE_URL> at <workspace SHA>`, lists the render fields and the fingerprint (measure 7) and opens once. `publish.md` records the approver, the basis, the time, the line and each step. *`test_publish.sh`: a changed plan; an unlisted approver; a failure injected after each step, then a rerun; an occupied repository.*
- **AC18** `bin/publish NAME --watch` applies measure 1's rule to the workflow runs on SHA (decisions 31, 32): it waits up to 5 minutes for a first run, then until every run is complete and none has started for 2 minutes, up to 30 minutes in all; it fails on a run concluding `failure`, `cancelled`, `timed_out`, `startup_failure` or `action_required`, on no run, or when no `check` job concluded `success`; `skipped` is not a failure. Run URLs and conclusions go in `publish.md`. *`test_publish.sh`, one case per conclusion and timing; live in G4.*

## 3. The foundation

- **AC19** The templates are exactly: `AGENTS.md` (what the repository is, from `DESCRIPTION`), `README.md` (`# {{NAME}}`, then `{{DESCRIPTION}}`), `GOVERNANCE.md` (§ Deciders, `- {{DECIDERS}}`), `CODE_OF_CONDUCT.md` (`{{COC_CONTACT}}`), `.github/CODEOWNERS` (`* {{CODEOWNERS}}`), `.github/ISSUE_TEMPLATE/config.yml` (`https://github.com/{{OWNER}}/{{NAME}}/…`), `docs/adr/README.md` (`{{WORKSPACE_URL}}`), and, holding no placeholder, every `.claude/skills/*/SKILL.md` and `.claude/agents/*.md`, stored as templates so none loads in the workspace (decision 91). The variants are `LICENSE.apache-2.0` (the Apache-2.0 text) and `LICENSE.none.tmpl` (`Copyright {{COPYRIGHT_HOLDER}}. All rights reserved.`). `foundation/bin/lib/layout.txt` names only product paths and lines no answer changes. The workspace's `foundation` check renders both fixture answers from `HEAD` (decision 100) and refuses any AC9 refusal, a selecting field lacking a variant for any allowed value, and a skill or subagent stored under its plain name. *`tests/test_check_foundation.sh`; `tests/m1.sh`.*

## 4. Foundation content, carried from the template spec

TAC1–TAC35, TAC37–TAC41, TAC43 and contracts C1–C4 hold for the foundation, reading "generated repository" as produced repository and "as generated" as the root commit `bin/verify` makes. Everything about `bin/init`, `template-only` blocks and `tests/generation.sh` is removed: TAC36 and TAC42 are dropped, TAC27 loses its generation step, and TAC41's fixed README opening and template block give way to AC19. With these amendments:

- **AC20** **Checks are files over shared libraries** (decisions 57, 95). Each check is an executable `bin/checks/<name>` whose second line is `# <description>` and third `# modes: <modes>`. `bin/check` sources `bin/lib/dispatch.sh`, which runs the checks in one given directory whose modes include the current one, with `CHECK_MODE`, `CHECK_BASE`, `CHECK_HEAD`, `CHECK_REF` and `DOCS_BASE` set, keeping TAC38's output and exit codes. `tests/run-all.sh` sources `tests/lib/runner.sh`, given a directory. The classifier, word lists, link resolver, status parser, script rules and secret patterns are libraries taking explicit parameters. *`test_check_cli.sh`: fixture checks passing, failing (exit 1), unable to run (exit 2), filtered by mode; `test_run_all.sh`.*
- **AC21** **Judged tree** (decision 44). Checks read files only through `bin/lib/tree.sh`: from `HEAD`'s objects in range mode, the index in staged mode, the working tree in tree mode, minus the path prefixes its caller excludes. CI checks out the head SHA with `fetch-depth: 0`; pre-push judges each pushed ref's tree. *`tests/test_tree_lib.sh`, incl. an excluded prefix; `test_check_cli.sh`: an uncommitted edit ignored in range mode; `test_check_docs.sh`: an RFC merged to `main` after branching does not fail the branch.*
- **AC22** **Docs base** (decision 50; amends C4). With an empty or all-zero BASE, the checked commits are those reachable from `HEAD` and from no remote ref other than `CHECK_REF` (CI sets it to the pushed branch, so a repository's first push checks its root commit), and the docs base is the parent of the oldest; a root commit means none. Staged mode with no `HEAD` (the root commit being made) has no docs base. *`test_check_cli.sh`: a first push where `origin/main` equals `HEAD`; a commit on an unborn branch.*
- **AC23** **Deciders at the docs base** (decision 45; amends TAC7). Each status-line or `**Decider:**` change on a chain doc names a decider listed at the docs base, or in the tree when there is none; `guard-docs.sh` refuses an agent edit inside § Deciders. *`test_check_docs.sh`: a decider added and used in one range refused; `tests/test_claude_hooks.sh`.*
- **AC24** `guard-docs.sh` simulates `replace_all` for `Edit` and each `MultiEdit` edit (decision 46). *`test_claude_hooks.sh`, fixture `# 0007 draft-handling`.*
- **AC25** **PR template** (decision 75; amends TAC23). `.github/pull_request_template.md` is upstream's file with a Summary section inserted before its `## What changed` line: `## Summary`, a blank line, a one-line comment prompt, a blank line. Removing the lines from `## Summary` up to `## What changed` gives blob id `c349e2c7a5bd35d293eea22e3937033b90a51879`; `layout.txt` pins it as `PATH<TAB>blob:<sha><TAB>minus:## Summary`. Once upstream carries the section, the entry pins upstream's new blob without `minus:`. `pr` requires no heading; Summary, What changed and How it was proved are required by `CONTRIBUTING.md` and counted by measure 8. *`tests/test_check_layout.sh`.*
- **AC26** **ADRs** (decision 58; amends decisions 15 and 17). ADRs 0001–0005 (the template plan's) and 0006 (the ICM workspace) are workspace files. A produced repository ships `docs/adr/README.md` linking them, its `CONTRIBUTING.md` § ADRs links that file (TAC40), and it numbers its own ADRs from 0001. *`docs` and `layout`, in `m1`.*
- **AC27** Every script exports `LC_ALL=C` before any pattern match (decision 88). *`scripts` (TAC37), product and workspace, refuses a script without it; `test_check_scripts.sh`.*

## 5. The workspace's CI, and what is enforced

- **AC28** `.github/workflows/ci.yml` (the workspace's) runs, on Ubuntu (bash 5, `shellcheck` v0.11.0 installed by pinned SHA-256, `REQUIRE_SHELLCHECK=1`) and macOS (bash 3.2): `bin/check --range`, `foundation/tests/run-all.sh` and `tests/run-all.sh`; job `m1` runs `tests/m1.sh` with `public.env` on Ubuntu and `private.env` on macOS; job `m5` renders both on both legs and fails unless each fixture's fingerprints agree (decision 84). `pr.yml` runs `bin/check pr`. *Their runs on every slice.*

| Enforcer | Refuses | ACs |
|---|---|---|
| The workspace's `disclosure`, `setup`, `foundation` | budgets; contract shape; bad Inputs; unnamed references; a stale questionnaire or setup file; a foundation that does not render | AC1–AC3, AC8, AC19 |
| The workspace's `commits`, `secrets`, `scripts`, `claims`, `trace` | as the product's (TAC8, TAC33, TAC37, TAC13, TAC12), on the workspace's own files | AC4, AC5, AC27 |
| `bin/ask`, `bin/render` | AC7's and AC9's cases; unpinned or mismatched trees | AC7, AC9–AC12 |
| `bin/verify` | a target unlike its render; a partial run; any failing check, suite or address | AC13, AC14 |
| `bin/publish` | a dirty, moved or unmerged workspace; an unverified target; a stale line; an unlisted approver; an occupied repository; a failed run | AC16–AC18 |
| The product's checks | TAC § 8, with AC20–AC27 | TAC |

**Not enforced:** (1) who confirmed the answers, and whether the operator saw them first; (2) that the named approver approved: an agent can pass the decider's name (decision 70); (3) that an agent loads only its stage's Inputs: `disclosure` checks the contracts, not the agent; (4) that the answers reflect the ask and the description meets the writing bar (stage 01's audit is the agent's); (5) `git` and `gh` commands an agent types in the workspace instead of `bin/publish`: the workspace has a deny list, not a command guard; (6) a local run from an unmerged commit (only `bin/publish` refuses one); (7) the conduct contact being real; (8) relative links outside agent files (decision 77); (9) status lines, deciders and ADR immutability in the workspace's own `docs/` (it runs no `docs` check), and the TAC30 rules on its own workflows; (10) TAC § 8's 22 items, for produced repositories; (11) a hook killed by a signal exits 143, which blocks only on a Claude Code release honouring `onFailure`; (12) what loads from `foundation/` when an agent reads product files there: `foundation/CLAUDE.md` loads and its `@AGENTS.md` import resolves to nothing; `foundation/.claude/rules/*.md` keep their `paths` scope; no skill or subagent loads, being stored as templates; `foundation/.claude/settings.json` and its hooks are not read, as Claude Code reads settings only at the project root.
