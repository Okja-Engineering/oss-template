# 0001 oss-template: spec

**Status:** draft. **Decider:** Matthew Van Dusen. **Rests on:** [`intent.md`](intent.md), [`research.md`](research.md), [`decisions.md`](decisions.md).

What the template does, stated so each line can be checked. Each acceptance criterion (AC) names its proof: a `bin/check` check, a suite under `tests/`, or a person reading. Unmarked ACs gate the build PR; **launch** ACs gate launch. The decider's rulings and every call made under ruling 12 are in [`decisions.md`](decisions.md), cited here as "decision N".

## Terms

- **Generated repository:** made with "Use this template", private or public. **As generated:** its single root commit `Initial commit`, before `bin/init`.
- **Upstream:** [`Okja-Engineering/ai-native-sdlc`](https://github.com/Okja-Engineering/ai-native-sdlc). The template applies and links it; it restates nothing beyond one-line summaries with a link.
- **Agent files:** `AGENTS.md`, `CLAUDE.md`, `.claude/rules/*.md`, `.claude/agents/*.md`, `.claude/skills/*/SKILL.md`. **Human docs:** `README.md`, `CONTRIBUTING.md`, `GOVERNANCE.md`, `SECURITY.md`, `CODE_OF_CONDUCT.md`, `CHANGELOG.md`.
- **Chain docs:** a work folder's `intent.md`, `spec.md`, `plan.md`; RFCs; ADRs. Each has a status line (C1).
- **Reserved decisions:** accepting or changing the status of a chain doc, an RFC disposition, approving a pull request. Only a decider listed in `GOVERNANCE.md` § Deciders makes them.

## 1. Which change needs what

| Rung | Use it when | Artifacts |
|---|---|---|
| PR only | Nothing anyone must agree first: typo, docs, dependency bump, refactor with unchanged behaviour, test-only | Pull request |
| Issue + PR | One PR; the intent fits in an issue (a bug fix, a small change with no real alternatives) | Issue with intent and validation method, then a PR with evidence |
| Work folder | More than one PR, a user-visible behaviour change, or a design with real alternatives | `docs/work/NNNN-slug/`: intent → spec → plan, a tracking issue, PRs |
| RFC | Changes a contract others depend on, the process itself (`CONTRIBUTING.md`, `GOVERNANCE.md`), or needs input beyond the maintainers | `docs/rfcs/NNNN-slug.md` on its own PR |
| ADR | Records a decision someone will later ask "why" about; any rung can produce one | `docs/adr/NNNN-slug.md` |

Pick the lowest rung that fits; when unsure, go one up. An accepted RFC is implemented through a work folder or an issue that links it. Filling § Deciders after `bin/init` is a PR-only change.

- **AC1** `CONTRIBUTING.md` § Which change needs what holds this table and rule; `AGENTS.md`'s first gate links it. *`layout`; `trace`.*

## 2. Work folders, RFCs, ADRs

**Work folders** `docs/work/NNNN-slug/`, numbered from `0001`. Chain docs start from `docs/templates/` via `bin/new`; other files are allowed. Deleting a whole work folder is allowed.

- **AC2** Refused by `docs`: a folder without `intent.md`; `spec.md` without `intent.md`; `plan.md` without `spec.md`; `spec.md` while `intent.md` holds an open marker; `plan.md` while `spec.md` holds one; an `accepted` or `done` doc holding one. A marker is the literal `[NEEDS CLARIFICATION:` outside code spans and fences. Passes: a deleted work folder. *`tests/test_check_docs.sh`, incl. fixture "plan with no spec".*
- **AC3** Refused by `docs`: names not matching C2; two folders, ADRs or RFCs sharing a number; a chain doc with no valid status line or no `**Decider:**` field. *`tests/test_check_docs.sh`.*
- **AC4** `bin/check docs --report` prints, per folder with no `plan.md` or a `plan.md` not `done`, exactly `docs/work/NNNN-slug: <doc> <state>, <n> open markers` (`<doc>` is the latest chain doc present); nothing when none. *`tests/test_check_docs.sh`.*

**RFCs** `docs/rfcs/NNNN-slug.md`, drafted as `0000-slug.md`, **renamed to the PR's number once the PR is open** (rust-lang/rfcs). Lifecycle (`CONTRIBUTING.md` § RFCs): discussion on the PR; when it settles, a decider posts a summary and proposes a disposition (**merge**, **close**, **postpone**); the **final comment period (FCP)** starts when every listed decider has signed off on the PR, label `S-fcp`, and lasts 7 calendar days; a new substantive objection restarts it. Merge: a decider sets `accepted`, then it merges. Close: unmerged. Postpone: label `S-postponed`, closed, reopenable. An accepted RFC is not substantially changed; a new RFC links the old one (decision 16).

- **AC5** Refused by `docs`: an RFC added in a PR not named with that PR's number (`PR_NUMBER` set); a status other than `draft` or `accepted DATE`. *`tests/test_check_docs.sh`.*

**ADRs** `docs/adr/NNNN-slug.md`, sequential, never reused; a generated repository's own start at 0006, after the inherited ones (decision 17). Sections: Context, Decision, Consequences, Alternatives considered. Status `proposed`, then `accepted DATE` or `rejected DATE`; an accepted ADR may become `deprecated DATE` or `superseded by NNNN DATE`, where ADR NNNN is accepted. **Once out of `proposed`, only the status line changes**, and only by those two transitions; a reversal is a new ADR (Nygard, 2011).

- **AC6** Against the docs base (C4) where an ADR is out of `proposed`, `docs` refuses: a change to any other line; any other transition; deletion; rename; `superseded by` naming an ADR that is missing or not accepted. Passes: a status-line-only change to `superseded by 0007 2027-01-03` with 0007 accepted. *`tests/test_check_docs.sh`, incl. fixture "edited accepted ADR".*
- **AC7** A status line that enters a decided state (any but `draft`, `proposed`) between the docs base and the tree names a decider listed in § Deciders at that tree; with no base, every decided status line counts as entering (decision 13). Passes: an accepted ADR whose decider is no longer listed, unchanged in the range. *`tests/test_check_docs.sh`.*

## 3. Commits

Upstream's convention applies by reference ([§ Commits](https://github.com/Okja-Engineering/ai-native-sdlc/blob/main/AGENTS.md#commits)): `type(scope)!: subject`, types `feat fix docs refactor test chore`, `!` optional, ≤ 72 characters (counted with `LC_ALL=C.UTF-8` and `${#s}`), no trailing period. Diverges where git or GitHub writes the subject, and bans tool credit rather than co-authors (decisions 20–23). One classifier, `bin/lib/classify.sh`, decides every subject for the commit-msg hook, range mode (pre-push, CI) and PR titles.

| Class | Matches | Result |
|---|---|---|
| conventional | the format above; a trailing ` (#N)` is ignored for length | pass |
| generated | `Revert "…"`, `Reapply "…"` (optional ` (#N)`); `Merge …`; `Initial commit`; `Squashed commit of the following:`; `Apply suggestions from code review` | pass. Range mode also requires `Merge …` to have two or more parents and `Initial commit` to be a root; any commit with two or more parents passes |
| work-in-progress | `fixup! `, `squash! `, `amend! ` | commit-msg passes; range mode refuses |
| other | anything else | refused |

The commit-msg mode classifies by subject alone (an amend hides merge and root state), so the hook can be laxer than range mode, never stricter. It first drops `#` comment lines and everything below git's scissors line. **Tool credit** is refused in every class: `noreply@anthropic.com`; `claude.com/claude-code`; a line starting `Generated with [` or `🤖 Generated with`; a `Co-authored-by:` line naming `claude`, `anthropic`, `copilot`, `codex`, `chatgpt`, `openai`, `cursor`, `devin` or `gemini` (any case). A person's `Co-authored-by:` passes.

- **AC8** Refused: `Update stuff`; `feat: add x.`; a 73-character conventional subject; `feat(Scope): x`; `revert: x`; `Initial commit` or `Merge branch 'x'` on a one-parent non-root commit in range mode; `fixup! x` in range mode; a body with `Co-Authored-By: Claude <noreply@anthropic.com>`. *`tests/test_check_commits.sh`; fixture "bad commit message".*
- **AC9** Passed: `feat!: drop x`; `Revert "feat: add x"` and `Reapply "feat: add x"`, both as range-mode commits and as message files fed to the commit-msg hook (`git revert` runs no commit-msg hook); `Revert "feat: x (#12)" (#13)`; two-parent `Merge pull request #4 from o/b` and `Merge branch 'main' into work`; root `Initial commit`, also after `--amend`; an amended merge; `chore: bump crazy-max/ghaction-github-labeler from 6.0.0 to 6.1.0`; a 72-character subject plus ` (#123)`; a 72-character subject with non-ASCII letters; `Co-authored-by: A Person <a@example.invalid>`; a body saying "the config is generated with jq". *`tests/test_check_commits.sh`, `tests/test_githooks.sh`.*

## 9. Measures

## Contracts

**C1 Status line.** Within a chain doc's first 5 lines: `**Status:** ` + state + optional `.` + free text, then `**Decider:** NAME` on the same line (on a draft: who will decide). Work docs `draft` | `accepted DATE` | `done DATE` (`plan.md`); RFCs `draft` | `accepted DATE`; ADRs `proposed` | `accepted DATE` | `rejected DATE` | `deprecated DATE` | `superseded by NNNN DATE`; DATE is `YYYY-MM-DD`. NAME runs to the next ` **` or line end, less one trailing period; it matches a § Deciders bullet in `GOVERNANCE.md` (text up to ` (`). One parser, `bin/lib/docs.sh`, serves `bin/check`, `bin/new` and `guard-docs.sh`.

**C2 Names.** `docs/work/NNNN-slug/`, `docs/adr/NNNN-slug.md`, `docs/rfcs/NNNN-slug.md`; slug `[a-z0-9]+(-[a-z0-9]+)*`; a `README.md` in those directories is ignored; templates live in `docs/templates/`.

**C3 Frontmatter subset** (bash can validate it; Claude Code's YAML parser accepts it). `key: value` (plain `[A-Za-z0-9][A-Za-z0-9 ,._/()'-]*`, or double-quoted with no inner quote) or `key:` then `  - "item"` lines. Keys: rules `paths` (list), `source` (one quoted value or a list); skills `name`, `description`; subagents `name`, `description`, `tools`. `source` values are a path to a human doc in this repository with optional `#anchor`, double-quoted.

**C4 `bin/check`.** `bin/check [CHECK…]`: tree checks, plus `commits` over `@{upstream}..HEAD` with docs base `git merge-base @{upstream} HEAD`; without an upstream, docs base `HEAD`. `bin/check --range BASE HEAD [CHECK…]`: tree checks plus `commits` over `BASE..HEAD`, `secrets` and `never-publish` over what `git merge-base BASE HEAD` to `HEAD` adds, docs base that merge base. An empty or all-zero `BASE` means commits reachable from `HEAD` and not from any remote ref, with docs base the merge base of `HEAD` and the remote default branch; only when none exists (a repository's first push) is there no docs base. `bin/check --staged`: tree checks, `secrets` and `never-publish` on the index, docs base `HEAD`. Also `commit-msg FILE`, `pr` (`PR_TITLE`, `PR_BODY`), `docs --report`, `--list`. Reads `PR_NUMBER`, `REQUIRE_SHELLCHECK`.
