# 0001 oss-template: spec

**Status:** draft. **Decider:** Matthew Van Dusen. **Rests on:** [`intent.md`](intent.md), [`decisions.md`](decisions.md), [`research.md`](research.md).

What the workspace does, stated so each line can be checked. Each acceptance criterion (AC) names its proof: a `bin/check` check, a suite under `tests/`, a CI job, or a person reading. Unmarked ACs gate the slice the plan assigns them to; **launch** ACs gate launch. "Ruling N" is one of the decider's rulings and "decision N" a decision made under the decider's delegation, both in [`decisions.md`](decisions.md). "Measure N" is the intent's numbering. "TAC N" cites AC N of the superseded template spec (`git show b368d09:docs/work/0001-oss-template/spec.md`), whose foundation ACs this spec carries by reference (§ 4); TAC44's M5, M6 and M7 are measures 6, 7 and 8 here.

## Terms

- **Workspace:** this repository. **Run:** one pass through the stages for one repository name. **Produced repository:** what a run makes. **Target:** the directory a run renders into, `<TARGET_ROOT>/<NAME>`, outside the workspace: a staging directory of rendered files that never holds a `.git` (decision 192). **Operator:** the person working through a run's checkpoints. **Published:** a run whose `publish.md` records an outward step done, or one of whose intended steps is seen done on the remote (decisions 101, 111, 120). **Attempted:** a run with an intent line in `publish.md` but neither; it resumes or is abandoned.
- **Foundation:** `foundation/`, the complete product tree (decision 68). A file there is **verbatim**, a **template** (`PATH.tmpl`) or a **variant** (`PATH.VALUE`, chosen by the field that selects `PATH`; decision 78). Nothing outside `foundation/` reaches a produced repository, and no product check runs on anything but a produced tree (decision 89).
- **Answers file:** a run's `stages/01-ask/output/<name>/answers.env`, one `FIELD=value` per line, read as data and never sourced. **Render fields** reach the produced tree; the others steer scripts only.
- **Fingerprint:** the git tree id of a rendered tree, file modes included (decision 53), built under hermetic git (AC10).
- **Share** (ruling 15): a step is **deterministic** (a script), **orchestration** (the contract's order and checkpoints) or **judgment** (the agent).
- **Reserved decisions:** TAC's, plus approving a publish plan (a decider in the workspace's `GOVERNANCE.md`, decision 70) and changing any § Deciders (decision 45).

## 2. The stages

Scripts do every write (decision 56). ICM keeps process out of code, and so does this: order and checkpoints stay in the contracts, and only the transforms are scripts, because prose cannot meet measure 5. `docs/workflow.md` says the workspace is pre-launch until S10 merges and G4 passes: until then `main` may hold an incomplete foundation. Four departures from ICM ([research](research.md), source 19) are recorded (decisions 85, 99, 108): the target is a staging directory outside `output/`, and so outside the workspace's own repository (decision 206); `references/` exists only when it holds files; Layer 0 is `@AGENTS.md`, with routing in `CONTEXT.md` and no What-to-Load table, since each contract's Inputs is its load list; and stage 02 has a checkpoint before `--replace`.

**Threat model** (decision 184). In scope: mistakes in the foundation or the answers (bugs, stale files, a failing check); the operator's own environment and git configuration (global and system config, templates, a `.git` left in the target by a reused directory or a hand edit, which the walk refuses; environment variables); the operator editing the target while a script runs; interrupted runs; secrets in answers or files. Out of scope, as a non-goal: a malicious foundation, or a malicious process running as the operator. The produced code is this workspace's own `foundation/`, reviewed and merged here and rendered from validated answers, and it runs with the operator's full access, so code that hostile could edit `bin/verify` itself; containing it would need an operating-system sandbox. The guards below serve the in-scope items, and none is claimed against the out-of-scope ones. The run's records (`answers.env`, `confirmed.md`, `render.md`, `verify.md`, `repo.git`, `publish.md` and the mirror) are written only by the workspace's scripts and are trusted across invocations; within one, verify and publish read their anchors once (AC13, AC16, AC17). `judge/`, which the produced run writes, is never read as a record (decision 198).

| Stage | Deterministic (script) | Orchestration (contract) | Judgment (agent) |
|---|---|---|---|
| 01-ask | `bin/ask run`, `confirm`, `--redo --remove` | checkpoints: confirm the answers; remove the target before `--redo` | drafts `NAME`, `DESCRIPTION`, `VISIBILITY`; audits the description |
| 02-render | `bin/render`, `--replace --remove` | a checkpoint: remove the target before `--replace` | none |
| 03-verify | `bin/verify` | stop on failure; a checkpoint: remove a target unlike its render; route to 01, 02, 03 again or the workspace | diagnoses the failure |
| 04-publish | `bin/publish --plan`, `--apply`, `--watch`, `--abandon` | checkpoints: a listed decider approves the plan line; the operator abandons an attempted run | presents the plan; diagnoses a failed run |

Each contract's `## Inputs` is one table, `| Source | File/Location | Section/Scope | Why |`, one row per file, the path as the File/Location cell's one code span (AC2, decision 221); below, a contract's Inputs gives those cells.

**01-ask.** Inputs: `../../shared/answers.tsv`. Process: draft the run fields from the ask; run `bin/ask run NAME FIELD=value…`; show the file. Checkpoints: the operator confirms (`bin/ask confirm NAME --by "<operator>"`), or gives edits; edits to an unpublished run first need the operator's yes to "remove <the target `render.md` names>", then `bin/ask run NAME --redo --remove "<path>" …` (decisions 94, 123). Audit: `DESCRIPTION` is one line meeting the writing bar of the upstream AI-native SDLC process: write it the way you would say it (ruling 19). Outputs: `answers.env`, `confirmed.md`.
**02-render.** Inputs: `../01-ask/output/<name>/confirmed.md`. Process: `bin/render NAME`; for a new render of the same answers, the operator's yes to "remove <path>", then `bin/render NAME --replace --remove "<path>"`. Outputs: `render.md`.
**03-verify.** Inputs: `../02-render/output/<name>/render.md`. Process: `bin/verify NAME`. On failure, stop and route as `docs/workflow.md` sets out: a target unlike its render, a dirty target or a partial run: a checkpoint here, which first names any `.git` the walk found in the target, where the operator approves "remove <the target `render.md` names>" (decision 206); with the yes, to 02 (`--replace --remove "<path>"`), and without it the target is left alone (decision 118); a check or suite failing in the produced run, or an audit finding tied to no answer, to a workspace fix merged by its own pull request like any other, then 02 renders afresh, which ends the route rather than cycling (decisions 193, 204); an answer refused, as `verify.md` records, or one the agent finds at fault, to 01 (`--redo`); a missing tool, install it and rerun 03; a target changed while verify ran: if no one edited the paths `verify.md` lists, the produced run wrote them, a workspace fix as above; otherwise `bin/verify NAME` once more, which judges the target against its render as usual (decisions 193, 204); a leftover verify could not remove, the operator removes the path it names, verify's own output from a failed or interrupted first run, then reruns 03 (decisions 197, 203, 211). The target is never edited by hand and never holds a `.git`. For a working repository the operator runs the clone command status prints (AC13), into a `<dir>` outside the target, then `bin/setup` there; `repo.git` stays verify's record and is never the clone's remote (decisions 158, 192, 199). Outputs: `verify.md`, `repo.git`, `judge/`.
**04-publish.** Inputs: `../03-verify/output/<name>/verify.md`. Process: `bin/publish NAME --plan`; checkpoint; `bin/publish NAME --apply "<line>" --approver "<decider>"`; `bin/publish NAME --watch`. A run may stop after 03 with a verified `repo.git` to clone. Once published, the operator's working repository is a clone of the published URL, by the command status prints from the URL `publish.md` records (AC13, AC15), then `bin/setup` there (decisions 192, 206). An attempted run is resumed with `--apply`, or, while nothing reached GitHub, abandoned at a checkpoint with `--abandon`. Once published, a run is never redone or replaced: a mistake, or a failed watch, is fixed in the produced repository through its own pull request process. Outputs: `publish.md`.

- **AC10** **Hermetic git** (decisions 90, 104, 112, 128, 132, 135, 137, 143, 154, 156, 159, 166, 167). `bin/lib/git.sh` sets this environment for every caller. Render, the fingerprint, verify (`repo.git` and `judge/`) and publish's mirror first unset every variable `git rev-parse --local-env-vars` names, `GIT_ATTR_SOURCE`, `GIT_DEFAULT_HASH`, and every `GIT_AUTHOR_*` and `GIT_COMMITTER_*`; then set `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_ATTR_NOSYSTEM=1`, `GIT_NO_REPLACE_OBJECTS=1` and `GIT_DEFAULT_REF_FORMAT=files` (git before 2.45 knows only `files`; from 2.45 the variable pins it; decision 156), and, through `GIT_CONFIG_COUNT`, `GIT_CONFIG_KEY_<n>` and `GIT_CONFIG_VALUE_<n>` so every git process they start inherits them while it keeps the environment, `core.attributesFile=/dev/null`, `core.excludesFile=/dev/null`, `core.fileMode=true`, `commit.gpgsign=false`, `core.hooksPath=/dev/null` and `core.fsmonitor=false`; its one version gate, comparing major and minor numerically, refuses a git older than 2.36.
